Antes de enviar

El sistema incluye a los inscritos vigentes que tengan un correo válido. Las personas sin correo se omiten. Por defecto, no se vuelve a enviar a quienes ya figuran como enviados para esa actividad. Cada mensaje se envía por separado; no se utiliza copia oculta (CCO) ni se comparte la lista de destinatarios.

El PDF adjunto utiliza la plantilla activa seleccionada en «Entradas PDF/ZIP». Revise esa vista previa antes de iniciar un envío masivo.

Crear cuenta de usuario

El correo será el nombre de usuario para iniciar sesión. Defina una contraseña y asigne el nivel de acceso. La cuenta quedará habilitada de inmediato; no se enviará una invitación por correo.

La contraseña no se muestra ni se almacena en esta aplicación. Entréguela al usuario por un canal seguro. Verifique cuidadosamente el correo: la cuenta se crea con el correo confirmado para permitir el acceso inmediato.

Notas de seguridad

  • La creación de cuentas se ejecuta en una función segura de Supabase; la clave privilegiada nunca se expone en el navegador.
  • Las cuentas se crean con correo y contraseña asignados por un administrador; no se envían invitaciones.
  • Asigne el rol de administrador solo a personas que realmente deban gestionar usuarios y permisos.
  • Active MFA en las cuentas administrativas cuando esté disponible para su proyecto.

Configuración de correo SMTP

La configuración pertenece exclusivamente a su organización. La contraseña SMTP se cifra en el servidor y nunca vuelve a mostrarse en el navegador.

Guía para configurar el correo

  1. Habilite un proveedor de correo transaccional que permita enviar mensajes desde una aplicación.
  2. En el panel del proveedor busque servidor SMTP (host), puerto, usuario y contraseña o clave SMTP.
  3. Registre y verifique el dominio o la dirección remitente. El proveedor debe autorizar el remitente configurado aquí.
  4. Copie los datos en este formulario. Para la mayoría de los proveedores, seleccione STARTTLS.
  5. Guarde y presione «Probar conexión». El estado verde indica que el servidor aceptó la conexión y autenticación.

Importante sobre los puertos: Supabase documenta restricciones de conexiones SMTP salientes por los puertos 25 y 587. Solicite a su proveedor un puerto alternativo habilitado; suelen utilizarse 2587 o 2525. El puerto 465 suele utilizar TLS directo y no figura entre las restricciones documentadas; si lo utiliza, seleccione «TLS directo». Confirme su disponibilidad con el proveedor y el entorno.

Ejemplo orientativo: AWS SES ofrece el puerto 2587 con STARTTLS. Utilice los datos propios de su cuenta y región.

Si el proveedor solo ofrece SMTP en los puertos restringidos, esta conexión directa no funcionará desde Supabase; utilice un proveedor con puerto alternativo o una integración de envío mediante API.

Para Gmail: use el host smtp.gmail.com, puerto 465 y seguridad TLS directo. El usuario y el correo remitente deben ser su dirección Gmail completa. Para autenticarse, use una contraseña de aplicación de Google, no la contraseña normal de su cuenta; Google exige tener activada la verificación en dos pasos para crearla. Crear una contraseña de aplicación.

Clave de cifrado: agregue una cadena aleatoria de al menos 32 caracteres llamada MAIL_SETTINGS_ENCRYPTION_KEY en Supabase → Edge Functions → Secrets. Esta clave cifra las contraseñas SMTP guardadas por cada organización; no es la contraseña SMTP del remitente.
